Axiomatic UI

Interfaces derived from first principles. People, tasks and the limits of perception go in. Every visual value comes out with its reason, and the rendered screen is checked against that reasoning.

Every visual difference must mean something, and every meaningful difference must be visible.

Generated UI fails both halves of that sentence at once. There's decoration that means nothing, and the one thing that needs the person looks like everything else. That happens because a model that doesn't know what matters picks the most common-looking option at every step. Axiomatic UI doesn't ban styles. It makes the agent know what each thing means, then encode exactly that.

      The twelve premises

      Facts about people and about encoding. Each comes with the number Axiomatic UI uses and what it decides. Every derived value cites at least one.

      The method

      Five agent skills and five commands. When something looks wrong, fix the cause: the model first, then the screen plan, then the code. Never patch a value inline.

      1 Modelaxiomatic-model: people, tasks (frequency, consequence, reversibility), text ranks, states. Facts from the owner, never invented.
      2 Deriveaxiomatic system: every value and its reason, as tokens named by meaning, plus derivation.md.
      3 Plan and buildaxiomatic-screen: salience order, actions with frequencies, and groups, then build with meaning tokens only.
      4 Verifyaxiomatic verify: render, measure, check against the plan, then look at the screenshots.
      5 Critiqueaxiomatic-critique: a fresh subagent asks what each difference means and what's missing.

      Where it stands

      • v0.2: engine, meaning-named tokens (CSS, TS, Kotlin), static lint, browser verifier, edit-time hook, five skills, 9 tests.
      • Building it surfaced real reasoning errors, and each one is now fixed in the engine. Confirming a constant action would have become a reflex. Text colors were never solved against the selection color. A rare action was a bigger target than the frequent one next to it.
      • Not yet: a real codebase with a real model (ALI is the obvious first), a fresh agent using the skills end to end, browsers other than Edge on Windows.
      • The salience measure is a tripwire, not a model of vision. The screenshots stay the judge.
