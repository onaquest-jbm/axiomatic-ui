Our Stripe webhook handlers run inline in the request and time out under load. Move them onto the job queue with retries and idempotency, and keep the existing signature check.

Plan: queue-backed webhook processing

I read through src/webhooks/ and the queue setup. Handlers are called synchronously from router.post('/stripe'), so a slow DB write delays the 200 response past Stripe's 10s limit.

Approach

  1. Verify the signature, then persist the raw event and return 202 immediately.
  2. Enqueue one job per event, keyed by event.id for idempotency.
  3. Move each handler into workers/stripe.ts with exponential backoff.

The new worker entry point looks like this:

workers/stripe.ts
export const worker = new Worker('stripe.event', async (job) => {
  const event = await events.load(job.data.id);
  if (event.processedAt) return;      // idempotent replay
  await handlers[event.type]?.(event);
  await events.markProcessed(event.id);
}, { connection, concurrency: 8 });
